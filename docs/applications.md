# Applications

The solution includes the Avalonia workbench, a batch converter, and benchmark harnesses. They demonstrate the public library APIs; reference `XISFLib` or `XISFLib.Windows` directly when integrating the library into another application.

The viewer binds workbench and utility state in `Viewer.Core`. Loading, selection, editor drafts, saving, diagnostics and calculations follow one implementation. Property dialogs use staged paging, and viewport state handles zoom/pan geometry. Avalonia provides native controls, dialogs, grid commits and bitmap handling. Writer defaults are zlib, SHA-256 and byte shuffling.

## Avalonia viewer

Run with the .NET 10 SDK:

```powershell
dotnet run --project XISFLib.AvaloniaViewer -c Release
```

It supports XISF/FITS loading, lazy image selection, full-resolution previews, linear/automatic stretching, Apply, zoom/pan, unload, the information tree, validation, image/document editing, raster import, attachments, all save modes and utilities. Session loading, rendering, editor parsing, raster decoding, save operations and utility calculations live in Viewer.Core. Use the mouse wheel to zoom and drag with the left button to pan. The image is presented before metadata and validation; failed loads retain the previous session.

The Image metadata tab supports property and FITS keyword add/edit/remove and **Apply metadata edits**. Applying commits the active grid cell and stages parsing before changing the working image. Matrix rows/columns, declared types, formats/comments, and repeated FITS commentary are retained. Unsupported property types and unavailable values are preserved as read-only rows. New unsupported text types and duplicate property IDs are rejected. Explicitly removing a preserved row removes that property.

Expandable sections also edit identifier/type/color space/orientation, offset, version-4 UUID, resolution, CFA, RGB working space, and display function. RGB luminance coefficients are derived from the primaries on Apply. Blank optional sections remove their metadata. The staged attribute parser ensures malformed values fail before changing the working image. Apply refreshes the preview, including orientation and DPI. Display-function editing stores its parameters; the automatic/linear preview controls retain their current stretch mode.

Switching images discards unapplied editor values; applied metadata stays with each working image. The Information tree and validation describe the loaded source until saving reloads the output. Loading another file or unloading discards working edits. Re-encoded saves also apply current editor drafts after committing active cells.

The first-image-table section edits scalar fields and rows using the shared syntax described below. Parsing finishes before any image edits are applied. Other tables and the first table's comment are retained. A blank table identifier leaves an existing table unchanged.

The Writer tab edits document metadata and properties, plus the creator-application setting. **Apply document edits** commits active cells and parses both grids before replacing the applied snapshot. Creation-time and creator-application properties are excluded from the initial metadata rows; output creation metadata follows writer policy. Document edits survive image switching and are cleared on load/unload. The creator setting persists. These controls prepare selected-image output; they do not imply preservation of every image or extension in the original container.

The viewer imports frame zero of PNG/JPEG/TIFF/BMP/GIF through Magick.NET-Q16-AnyCPU 15.0.0 into UInt8 RGB/RGBA. It detects actual transparency, retains decoded DPI and omits alpha/ID/resolution from imported thumbnails. Import does not promise preservation of high-bit raster storage, EXIF orientation, every TIFF variant or embedded color-profile rendering. Raster format signatures are restricted before invoking the decoder. ICC attachment preserves profile bytes subject to the XISF writer's header normalization/validation. Import and attachment reads run away from the UI thread.

The Utilities tab exposes astronomy metadata, sampled statistics, histograms (up to 65,536 bins), interleaved region/channel reads with a 64-value preview, and FITS WCS transforms using zero-based pixel coordinates. Heavy calculations run on workers; display stretching does not alter scientific samples. Writer settings and save modes follow the behavior below.

The **Statistics** tab provides on-demand image quality analysis with cancellation. Select a zero-based channel (RGB defaults to green), set a detection threshold from 3 to 50 sigma (default 5), then choose **Analyze image**. Display stretching leaves the results unchanged. Selection, reload, import, applied image metadata and analysis-setting changes clear results. Analysis runs on a worker and is serialized with other image operations.

Metrics include detected star candidates and density, saturated peaks, median Gaussian-equivalent FWHM in pixels, eccentricity, estimated peak SNR, background, noise, background variation, percentile signal span, finite/non-finite counts, min/max, mean/standard deviation, clipping rates and sampled channel statistics. Each row explains its method; hover over its explanation to read the full text. The full selected channel is scanned for counts and moments. Medians/percentiles and channel summaries use at most 65,536 systematic samples; horizontal/vertical neighbor differences estimate noise as `1.4826 × MAD / sqrt(2)` under an independent Gaussian-noise assumption. Background variation uses the 90th minus 10th percentile of 128-pixel tile medians.

Star detection uses local tile background and two-pixel-radius local maxima, then a six-pixel-radius aperture with background-subtracted positive weights for second moments. Candidates need at least three central pixels above two sigma and an estimated width from 1 to 8 pixels. The six-pixel image border, saturated apertures and non-finite apertures are excluded. Overlapping tiles count each owned peak once. Star counts cover the image; shape/SNR summaries retain at most the first 65,536 accepted candidates. Widths are moment estimates, not fitted PSFs. Blends, undersampling, extended sources and broad stars can affect detection or be missed; this is not a catalog-complete star count. General source-detection considerations are described in the [Photutils guide](https://photutils.readthedocs.io/en/stable/user_guide/detection.html); the viewer uses its own heuristic detector.

Peak SNR is `(peak − local background) / estimated noise`, and signal-span/noise is a contrast diagnostic. Neither is calibrated photometric SNR: physical CCD SNR needs source/sky/dark signals, gain and read noise, as in [Astropy's CCD SNR contract](https://docs.astropy.org/en/stable/api/astropy.stats.signal_to_noise_oir_ccd.html). Correlated noise, processing, CFA patterns, nebulosity and gradients bias these estimates. Debayer before comparing star shapes. Bounds-based clipping does not establish camera saturation. Zero/unavailable noise produces unavailable detection/SNR rather than invented values. Analysis supports two-dimensional UInt8/16/32/64 and Float32/64 images; UInt64 double estimates can round above `2^53`. Scientific pixels are never modified or retained in an analysis cache.

### Finish & share

For a simple finished picture, load an image and click **Finish & share** in the sidebar. It opens a separate preview and automatically prepares the selected working image. The tab also has **Create finished image**, **Cancel**, **Save PNG…** and **Save JPEG…** buttons. No expert processing settings are required. **Reduce noise**, **Sharpen stars** and **Reduce star spikes** are enabled by default; each can be disabled before recreating the preview. Changing a switch clears the previous finished picture, and the switches retain their choices across image loads. Creation and PNG/JPEG export show the current stage and a progress bar immediately. The bar shows progress within measurable stages and animates during stages without reliable percentages; it does not estimate remaining time. Cancel also applies to exports, with cancellation checked before publishing the staged file. Review the preview before saving; the export uses those exact finished pixels rather than the current scientific display stretch. Applied image changes, selection, import, reload and unload clear the finished picture. Unapplied metadata drafts are not committed by this workflow.

Automatic cropping trims contiguous edge lines that are at least 99% empty (zero at the declared lower bound, non-finite or fully transparent), capped at 20% of the original dimension on each edge. Nonzero negative samples count as content. Retained dimensions of at least 256 pixels receive an additional 1% tidy trim on each side. Empty frames keep their full dimensions. For scientific frames with missing corner coverage, a sampled occupancy grid finds the largest populated rectangle containing the image center, provided it retains at least 70% of the field area and each dimension before the tidy trim. This removes common mosaic corner gaps without cropping around a target. Sampling can miss small holes, and severely incomplete coverage remains rather than discarding most of the field. Raster imports skip this additional coverage crop.

Dark scientific data (sampled normalized median below 0.18) receives a linked adaptive stretch targeting a background of 0.10, with shadows at −2.8 robust sigma. Higher-background scientific data also receives this stretch when its positive robust spread (`1.4826 × MAD`, averaged across nominal channels) is below 10% of its mean channel median. This distinguishes narrow high-offset linear data from broad already-developed distributions; brightness alone does not establish whether an image is already stretched. High-offset inputs are recentered before adaptation to avoid interpreting backgrounds above 0.5 as inverted images. RGB backgrounds are balanced using channel medians before stretching. Constant/high-contrast bright frames and raster imports retain their exposure. This aesthetic background balance is not photometric color calibration and can change the appearance of fields dominated by extended emission. Gentle selective blur, thresholded unsharp masking and a small RGB saturation boost improve the sharing copy; smoothing/sharpening thresholds adapt to sampled display noise. These use the existing Magick.NET dependency. [ImageMagick documents these filtering operations](https://imagemagick.org/command-line-options/).

Noisy stretched scientific frames (estimated display luminance noise at least two 8-bit levels) also receive three-scale undecimated B3-spline wavelet denoising before cosmetic filters and star restoration. Luminance and red/blue differences are treated separately, with stronger color-noise suppression. Each scale estimates noise directly from robust local wavelet dispersion, accommodating some correlated stacking noise. Firm shrinkage retains coefficients above three thresholds, helping protect stars and nebular edges. An isolated negative luminance outlier at the finest scale is additionally damped only when all four neighbors are brighter; coherent dark edges retain their significant coefficients. Very faint texture can still be suppressed. Bounded 192-pixel tiles have 14-pixel halos covering the complete convolution support. Temporary output bytes and fixed-size workspaces are released after processing; no scientific-image cache is retained. Stage progress and cancellation operate between tiles/scales. **Reduce noise** disables this additional pass; developed rasters and low-noise frames skip it. This is aesthetic display denoising, not improved scientific SNR or recovered missing signal. Astronomical noise methods and their resolution tradeoffs are discussed in this [comparative study](https://arxiv.org/abs/2009.01846).

Before stretching, eligible scientific frames of at least 96 × 96 pixels receive conservative automatic gradient reduction. Each nominal channel uses a 12 × 12 grid with at most 256 samples per tile. Tile medians suppress sparse stars; an iteratively sigma-clipped plane rejects both unusually bright emission/halos and dark clouds. The fit needs at least 75% populated tiles, 60% retained fit tiles, support in every quadrant, and a slope span exceeding twice the robust residual scatter. Only 80% of the fitted slope is subtracted, retaining the central sky level; the stretch is then recomputed from corrected samples. A plane cannot chase local nebula structure or fit Alnitak's radial halo. Raster imports, already-developed frames and unreliable fits skip correction. Sampling and source rejection follow the general principles in the [Photutils background guide](https://photutils.readthedocs.io/en/stable/user_guide/background.html); the viewer implements its own limited plane fit. Very broad emission or dark clouds spanning most of the frame can still be confused with sky gradients. This is aesthetic reduction rather than calibrated sky subtraction, and curved gradients or optical halos can remain. The preview summary reports when correction was applied.

Star restoration is limited to scientific data classified as linear by the finishing workflow; developed raster images skip it. A tiled green-channel (or Gray) detector retains at most the strongest 16,384 round, resolved star candidates above eight local noise sigma. Hot pixels, incomplete apertures, broad wings and close blends are rejected for deconvolution, and any channel clipping at normalized 0.98 excludes its patch. Isolated stars above 15 sigma receive five damped Richardson–Lucy iterations on 21 × 21 per-channel patches, with a normalized separable Gaussian PSF estimated from stellar width and bounded to sigma 0.6–1.5 pixels. Noise floors, bounded update ratios, limited peak growth and feathered signal masks constrain amplification. The linear corrections are mapped through the same stretch and added after cosmetic smoothing so the smoothing does not undo star restoration. Original buffers remain untouched. This is local aesthetic restoration with an approximate PSF, not a measured optical reconstruction or scientific flux-preserving deconvolution. Deconvolution exchanges noise for resolution; see the [STScI restoration discussion](https://hst-docs.stsci.edu/drizzpac/chapter-3-description-of-the-drizzle-algorithm/3-1-imagereconstructionandrestorationtechnique) and [Richardson–Lucy reference implementation](https://scikit-image.org/docs/stable/api/skimage.restoration.html#skimage.restoration.richardson_lucy).

Spike reduction groups structured bright cores and examines at most 32 distinct bright candidates and searches for narrow angular peaks with coherent opposite rays from outside the core to at most 128 pixels. Transverse comparisons at 6–16 pixels estimate ray excess; angular contrast/width checks reject ordinary round halos, and neighboring detected stars are protected. At most three opposite ray pairs per star receive feathered 25–40% attenuation, independently in each nominal channel. It softens supported rays rather than reconstructing hidden detail or removing all diffraction spikes, optical halos or irregular starbursts. A filament crossing a bright star can resemble a spike, so review the preview and disable the switch if nearby structure is affected. The summary reports how many stars received each effect. The algorithms use bounded catalogs and local workspaces, with stage progress and cancellation between scan rows, stars and iterations.

The output is an opaque, full-resolution 8-bit RGB picture, flattened onto black, with source orientation and valid DPI retained (DPI axes swap for quarter turns). PNG preserves the finished preview pixels and uses compression level 3 for responsive export; this changes file size, not pixels. JPEG uses quality 95 and introduces compression loss. PNG compression is set separately from JPEG quality, because ImageMagick interprets quality 95 as slow level-9 PNG compression ([encoder settings](https://imagemagick.org/command-line-options/#quality)). This copy does not retain scientific sample precision, astronomy metadata or astrometry. Original buffers and metadata are untouched, and export cannot overwrite the loaded/imported source path. PNG/JPEG writes stage in the destination directory, so an existing destination survives encoding failure or cancellation. Native filtering/encoding stages have cancellation checkpoints rather than interruption inside each native operation.

Finishing supports two-dimensional UInt8/16/32/64 and Float32/64 Gray/RGB images with optional alpha. CFA mosaics require an already-debayered image; unsupported spaces, volumes and complex/binary128 storage report a clear limitation. UInt64 processing uses double display estimates. Colors are treated as RGB for sharing; arbitrary source ICC/working-space calibration is not inferred. The state retains one explicit finished pixel buffer for review/export; replacing or clearing it releases the buffer, and Avalonia disposes the corresponding preview bitmap on the UI thread.

### Save behavior

| Mode | Output and preservation |
| --- | --- |
| Byte-identical copy | Available for loaded monolithic XISF and enabled by default. Copies the complete source, including all images, metadata, extensions and signatures. Editor changes and writer settings are not applied. Saving to the same path leaves the source unchanged. |
| Re-encoded XISF | Clear **Byte-identical copy**. Applies editor changes and compression/checksum/shuffle settings, then writes the selected image and configured document metadata. |
| Distributed XISF | Writes a `.xish` header and a sibling `.xisb` file for the selected image. |
| FITS | Writes the selected image as FITS with checksums. XISF compression settings do not apply. |

Re-encoding can change XML ordering, creation metadata, attachments and file size. It does not retain every unknown extension, original signature or other image/HDU. Saved output is reloaded and its conformance diagnostics are displayed. The library's loaded-document writer provides broader XML and opaque-block preservation; see [I/O contracts](io-and-limitations.md) and [specification coverage](specification-compliance.md#compatibility-and-preservation).

### Editor limits

The viewer shows single-line property previews of at most 256 value characters, with a character count for longer text. Selecting an image-property row shows its identifier above the grid. Use **Open…** to inspect or edit the complete value in 4,096-character pages, or export the full text as UTF-8. **Accept edits** stages the edited value in the row; use Apply or re-encoded Save to apply it. Closing the dialog discards its staged changes. Unsupported types remain read-only. A page accepts up to 8,192 characters; edit additional pages or use the library API for larger insertions.

Previews never replace property content. Large numeric arrays show an element count and are formatted on a worker only when opened; unchanged arrays retain their original typed values, shape, format and comment. The Information tree also uses bounded summaries. Property grids use finite viewports and fixed-height rows so serialized spline models cannot expand the scrolling layout.

The workbench's text editors cover fewer types than the library. Scalar editing supports strings, Boolean, integers through 64 bits, Float32/64 and timestamps. Numeric vector/matrix editing supports integers through 128 bits and Float32/64, with comma-separated values and explicit matrix dimensions. Complex and binary128 values and unavailable properties are preserved as read-only rows; new values require the typed library APIs. Use the typed library APIs to edit them, or byte-identical copy to preserve an unchanged monolithic file.

Table fields use one `id|type|label|format` definition per line; label and format are optional. Rows use one line per row with pipe-separated cells matching the fields. The viewer edits only the first image table. Tables containing array/unsupported/null cells, delimiters, or cell text that this syntax cannot round-trip remain read-only and are preserved unchanged. Use the typed library APIs to edit them. Scalar timestamps retain fractional seconds and offsets.

## Batch XISF-to-FITS converter

```powershell
dotnet run --project XISFLib.Convert -c Release -- "D:\Astro\Captures" 4
```

The folder argument is required; the optional positive concurrency argument defaults to eight. Only `.xisf` files directly in that folder are processed, with case-insensitive extension matching. Each produces a sibling `.fits` file containing all its images. Existing outputs are refused, source files are retained, and failed conversions do not stop the remaining files. Progress messages may appear out of order. Lower concurrency for large files to reduce peak memory use.

| Exit code | Meaning |
| --- | --- |
| 0 | Success, including an empty input folder |
| 1 | Conversion or enumeration failure |
| 2 | Invalid arguments |

Existing FITS keywords take precedence. Missing standard cards are populated from native XISF astronomy properties, with image properties taking precedence over global properties. Center RA/DEC is stored in degrees; native astrometric models are not translated into FITS WCS.

An `XISFMETA` binary-table extension archives the original XML header and decoded global/image properties as UTF-8 XML in a `METADATA` byte column. This preserves Unicode and property arrays beyond ordinary FITS cards. It does not copy ancillary binary attachments or convert XISF tables into FITS tables; original XML block locations still refer to the source XISF. Keep the source for full-fidelity recovery. Complex images cannot be converted to standard FITS image HDUs. See [conversion limits](io-and-limitations.md#conversion-and-numeric-precision).

The metadata archive is a batch-application feature. The core `FitsConverter` APIs perform image/metadata conversion without automatically adding this archive.

## Benchmarks and example files

Use Release builds. The default benchmark accepts an examples-folder argument and measures `slow.xisf` and `slow.fits`. The specialized `--performance` and `--fits-performance` modes cover synthetic processing and the FITS examples. The Avalonia viewer provides `--benchmark` for staged native loading. The [performance guide](performance.md) contains complete commands and explains allocation and timing limits.

The repository's `Examples` folder includes real XISF/FITS inputs. `Examples/README.md` documents provenance and fixture caveats; `sources.json`, `validation.json`, and `fits-validation.json` record downloaded XISF sources and validation results. Example files are test/benchmark inputs and are not required by library consumers.
